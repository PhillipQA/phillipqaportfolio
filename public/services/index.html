BUG-014 · CheckoutIllustrative example

Retrying after a declined card creates a duplicate order

Severity: High Staging build Chrome · Windows 11
Steps to reproduce
  1. Add any item to the cart and go to checkout.
  2. Pay with a test card that is declined.
  3. When the decline message appears, pay again with a valid test card.
  4. Open the order history.
Expected
One order, charged once.
Actual
Two orders: one “Payment failed” and one “Paid.”
Impact
Customers see an order they never completed, which is likely to generate support tickets and may reserve stock twice.
Evidence
Screen recording and network log attached.
To verify the fix
Repeat the steps and confirm a single order and a single charge.

A few practical details.

What do I need to provide?

A staging or test environment, test accounts, requirements or expected behavior, and a list of the workflows that matter most. API and database checks require the relevant access.

Can you work with my developers or agency?

Yes. I can document findings in your existing issue tracker or an agreed report format, and coordinate fix verification with your team.

Do you fix the bugs or guarantee a bug-free release?

These packages cover testing and reporting. Your development team handles fixes. Testing reduces uncertainty within the agreed coverage; it cannot guarantee that every defect will be found.

Can I request API testing or automation?

Yes. API and SQL checks can be included when they fit the scope and access available. Automation setup is discussed and quoted separately after reviewing your application.
